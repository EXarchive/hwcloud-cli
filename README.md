# 智慧课堂工作台

一节课要用的四件事收在一个页面里：**签到 → 随机点名 → 随堂测 → 课堂看板**。纯前端、无后端、打开即用。

## 四块能力

| 模块 | 做法 | 关键点 |
|------|------|--------|
| **签到** | 6 位签到码 + 点名字即签到 | 重复签到幂等（不会重复计数）；结束签到后拒绝新签到 |
| **随机点名** | 权重 `1 / (1 + 已点次数)` | 不是均匀随机——被点过的人权重下降，长期趋近公平，避免总点同一人 |
| **随堂测** | 单选题库 + 提交判分 | 校验答案数量与题目数量一致；返回逐题对错明细 |
| **课堂看板** | 出勤率 / 平均分 / 分段分布 / 参与度 | 参与度 = 提交人数 ÷ 实到人数 |

## 交互实测

用 headless Chromium 跑完整链路：

```
CHIPS: 8 | PRESENT: 3 | RATE: 37.5%
PICKED: 张三
RESULT: 张三 得分 100 分（答对 3/3）
AVG: 100
ERRORS: none
```

即：8 人名单点 3 人签到 → 出勤率 37.5% → 点名点到张三 → 三题全对得 100 → 看板平均分 100、参与度 33.3%（1/3），全程零 console 错误。

## 随机点名的公平性

朴素 `random()` 在 20 人的班里，20 次点名大约有 26% 概率有人被点两次以上、也必然有人一次没被点到。这里用「次数越少权重越高」的加权抽样，单测验证：

```
✔ 随机点名趋于公平：100 次后每人至少被点 5 次
```

5 人名单点 100 次，最少的也点到 5 次以上（均匀期望是 20 次；加权后分布更平）。

## 目录结构

```
smart-classroom/
├─ index.html              # 工作台界面（四块面板）
├─ src/classroom.js        # 纯逻辑：签到 / 点名 / 随堂测 / 看板
└─ tests/classroom.test.mjs
```

## 设计取舍

- **逻辑与界面分离**：`classroom.js` 全是纯函数 + 可变 session 对象，方便单测；界面只负责渲染与事件转发。
- **可复现随机**：点名用可注入种子的 xorshift，测试里能稳定复现，线上用 `Date.now()` 当种子。
- **不引第三方图表库**：看板的分段分布用纯 CSS 柱条，避免为了一个小图引入 1MB 依赖。
- **不做账号体系**：一节课一个 session 对象，刷新即重置——课堂场景不需要持久化到后端。
